# منظومة النسخ الاحتياطي التلقائي وتصفير العام الدراسي (Backups & Annual Academic Reset)
> **EduCenter ERP** — نظام إدارة السنتر التعليمي المتكامل  
> **الإصدار البرمجي:** 1.0.0 | **تاريخ التوثيق:** نوفمبر 2026

---

## 1. محرك النسخ الاحتياطي لقاعدة البيانات (Database Backup Engine)

صُممت منظومة النسخ الاحتياطي في **EduCenter ERP** لتوفير حماية مطلقة لكافة بيانات السنتر ضد الكوارث أو تلف الأجهزة أو الأخطاء البشرية.

### 1.1. آلية إنشاء النسخة الاحتياطية
- **محرك التصدير الصامت:** يعتمد النظام على أداة `pg_dump` الرسمية لتصدير هيكل وجداول وبيانات قاعدة بيانات PostgreSQL كاملة بما يشمل الفهارس والقيود.
- **الضغط الفائق (`Gzip Compression`):** يتم ضغط مخرجات التصدير مباشرة أثناء توليدها باستخدام خوارزمية `gzip`، مما يقلل حجم ملف النسخة الاحتياطية بنسبة تصل إلى **85%** ويوفر المساحة وسرعة الرفع السحابي.
- **بصمة التحقق التشفيرية (`SHA-256 Checksum`):** يقوم النظام فور إتمام الملف بحساب بصمة تجزئة مشفرة للملف كاملاً وتخزينها في جدول `backup_records` لضمان عدم تعرض الملف للتلف أو التعديل أثناء النقل والتخزين.
- **تسمية الملفات القياسية:** تُسمى الملفات بنمط زمني موحد:  
  `backup-educenter-YYYY-MM-DD-HHmmss.sql.gz`

---

### 1.2. المحركات السحابية وسياسة الإبقاء (Cloud Drivers & Retention)
1. **التخزين المحلي الآمن (`Local Storage`):**  
   يتم حفظ النسخ في مسار التخزين المخصص داخل الخادم (`storage/backups/`).
2. **المزامنة السحابية مع Google Drive:**  
   دعم كامل للربط مع Google Drive API عبر حساب خدمة أو OAuth2؛ حيث يتم رفع النسخة فور إنشائها تلقائياً إلى مجلد محدد على السحابة مع تجديد التوكن تلقائياً.
3. **المزامنة السحابية مع Dropbox:**  
   دعم متزامن للرفع إلى Dropbox لضمان وجود نسخ متماثلة على خوادم متعددة جغرافياً.
4. **سياسة الإبقاء والتدوير التلقائي (`Retention Policy`):**  
   لتفادي امتلاء القرص الصلب، يحدد المشرف حداً أقصى للنسخ المحتفظ بها (افتراضياً 30 نسخة). عند تجاوز هذا الحد، يقوم النظام تلقائياً بحذف النسخ المحلية الأقدم مع الاحتفاظ بأحدث 30 نسخة.

---

### 1.3. بروتوكول استعادة النسخة الاحتياطية (`Restore Protocol`)
- **حماية أمنية مشددة بكلمة المرور:** نظراً لخطورة عملية الاستعادة (التي تعيد قاعدة البيانات إلى تاريخ النسخة)، لا يُسمح بتنفيذها إلا لمستخدم يملك صلاحية `backups.manage`، مع **إلزامية إدخال كلمة مرور حسابه الشخصي الحالية والتحقق منها بخوارزمية `Argon2`** قبل بدء الاستعادة.
- **فك الضغط والاستيراد الذري:** يتم فك ضغط النسخة مؤقتاً وتشغيل أمر `psql` لاستعادة كافة السجلات، تليها عملية مسح للكاش المؤقت للنظام وتدوين العملية في سجل التدقيق الأمني.

## 2. بروتوكول تصفير وبدء العام الدراسي الجديد (Annual Academic Reset)

مع نهاية العام الدراسي وتخرج الدفعات، يحتاج السنتر إلى أرشفة وتصفير العمليات التشغيلية والمالية المنتهية وبدء عام جديد بنظافة تامة دون فقدان بيانات التأسيس أو السجلات التاريخية.

### 2.1. مسار الأمان الخماسي لبدء العام الدراسي

```
  [طلب بدء عام دراسي جديد]
            │
            ▼
  [1. فحص رمز الأمان PIN الصارم]
  - مقارنة متطابقة زمنياً (Timing-Safe Comparison)
  - منع هجمات قياس التوقيت (Timing Attacks)
            │
            ▼
  [2. النسخ الاحتياطي الإجباري المسبق (Pre-Purge Backup)]
  - أخذ نسخة كاملة (.sql.gz) من قاعدة البيانات فوراً
  - في حال فشل النسخ، تلغى العملية برمتها دون مساس بأي سجل
            │
            ▼
  [3. التصفير التشغيلي الذري (Atomic Transactional Purge)]
  - تنفيذ الحذف داخل Transaction واحدة
  - حذف الحضور، التعويضات، الدفعات، المستحقات، الحجوزات، والحصص
  - خيار حذف الطلاب (purgeStudents = true / false)
            │
            ▼
  [4. تحديث العام الدراسي الجديد]
  - تعديل academicYear في system_settings (مثلاً "2027 / 2028")
            │
            ▼
  [5. إبطال الكاش الشامل وتدوين سجل التدقيق]
  - مسح كافة الكاشات وتدوين العملية مع رقم النسخة الاحتياطية
```

---

### 2.2. التحقق الآمن من رمز الأمان (`Timing-Safe PIN Verification`)
لمنع هجمات تحليل وقت الاستجابة، تتم مطابقة رمز الأمان السري للعمليات الكبرى باستخدام:
```typescript
private verifyPinTimingSafe(inputPin: string, expectedPin: string): boolean {
  if (!inputPin || !expectedPin || inputPin.length !== expectedPin.length) {
    return false;
  }
  const bufA = Buffer.from(inputPin);
  const bufB = Buffer.from(expectedPin);
  return crypto.timingSafeEqual(bufA, bufB);
}
```

### 2.3. المقارنة بين التصفير القياسي والتصفير الشامل للطلاب

| الميزة | التصفير القياسي (`purgeStudents = false`) | التصفير الشامل (`purgeStudents = true`) |
| :--- | :--- | :--- |
| **النسخة الاحتياطية الإلزامية** | ✅ تُنشأ تلقائياً قبل البدء | ✅ تُنشأ تلقائياً قبل البدء |
| **سجلات الحضور والتعويضات** | 🗑️ يتم تصفيرها بالكامل | 🗑️ يتم تصفيرها بالكامل |
| **المعاملات والدفعات المالية** | 🗑️ يتم تصفيرها بالكامل | 🗑️ يتم تصفيرها بالكامل |
| **الحجوزات وجداول الحصص** | 🗑️ يتم تصفيرها بالكامل | 🗑️ يتم تصفيرها بالكامل |
| **اشتراكات المجموعات (`enrollments`)** | 🗑️ تصفير الاشتراكات لبدء تسجيل جديد | 🗑️ تصفير الاشتراكات |
| **بروفايلات الطلاب (`students`)** | 🛡️ **محفوظة** دون حذف | 🗑️ **تُحذف بالكامل** لبدء قاعدة طلاب جديدة |
| **المجموعات والسياسات المالية** | 🛡️ **محفوظة** لاستخدامها العام القادم | 🗑️ تُحذف مع الطلاب |
| **المدرسين والمساعدين والقاعات** | 🛡️ **محفوظة دائماً** | 🛡️ **محفوظة دائماً** |
| **الاستخدام المثالي** | الانتقال الطبيعي بين الأعوام الدراسية مع بقاء الطلاب المقيدين في السنتر | إعادة تهيئة المركز أو انتقال ملكيته أو بدء مرحلة جديدة تماماً |
