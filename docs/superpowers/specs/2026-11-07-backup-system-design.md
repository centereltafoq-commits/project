# نظام النسخ الاحتياطي السحابي والمحلي واستعادة البيانات (Backup & Disaster Recovery Subsystem)

## 1. نظرة عامة والهدف (Overview & Goals)
يهدف هذا النظام الفرعي إلى تأمين بيانات "مركز الأستاذ محمد التعليمي" بالكامل ضد أي فقدان طارئ أو عطل في الأجهزة، وذلك عبر أتمتة عمليات إنشاء النسخ الاحتياطية لقاعدة بيانات PostgreSQL، وضغطها، وتوزيعها على وجهات تخزين متعددة تشمل:
1. **المسار المحلي / الفلاشة الموصولة / الديسك توب (Local / USB Flash / Desktop Path).**
2. **التحميل المباشر عبر المتصفح (Instant Direct Browser Download).**
3. **التخزين السحابي Google Drive بنقرة واحدة (One-Click Google OAuth Connect).**
4. **التخزين السحابي Dropbox.**
5. **الاستعادة الذاتية الآمنة مع التحقق الأمني بكلمة مرور المشرف (Secure One-Click Restore).**

## 2. هيكل البيانات (Database Schemas)

### جدول `backup_settings` (إعدادات النسخ الاحتياطي)
| الحقل | النوع | الوصف |
| :--- | :--- | :--- |
| `id` | UUID (PK) | المعرف الفريد للإعدادات (صف مركزي واحد) |
| `auto_backup_enabled` | BOOLEAN | تفعيل/تعطيل الجدولة التلقائية اليومية (افتراضي: `true`) |
| `schedule_time` | VARCHAR(8) | توقيت التنفيذ اليومي بصيغة 24 ساعة (افتراضي: `'02:00'`) |
| `retention_count` | INTEGER | عدد النسخ المحتفظ بها محلياً وسحابياً قبل التنظيف (افتراضي: `30`) |
| `local_path` | VARCHAR(500) | مسار مجلد محلي على القرص أو الفلاشة (مثال: `C:\Users\Mohamed\Desktop\EduCenter_Backups`) |
| `google_drive_enabled` | BOOLEAN | تفعيل رفع النسخ الاحتياطية على Google Drive |
| `google_drive_tokens` | JSONB | رموز OAuth والبريد المربوط ومجلد التخزين المخصص |
| `dropbox_enabled` | BOOLEAN | تفعيل التخزين في Dropbox |
| `dropbox_tokens` | JSONB | رموز الربط مع دروب بوكس |
| `updated_at` | TIMESTAMPTZ | تاريخ آخر تعديل للإعدادات |

### جدول `backup_records` (سجل عمليات النسخ الاحتياطي)
| الحقل | النوع | الوصف |
| :--- | :--- | :--- |
| `id` | UUID (PK) | معرف سجل النسخة الاحتياطية |
| `file_name` | VARCHAR(255) | اسم ملف النسخة الاحتياطية (مثال: `backup-educenter-2026-11-07-020000.sql.gz`) |
| `file_size_bytes` | BIGINT | حجم الملف الفعلي بالبايت |
| `trigger_type` | VARCHAR(32) | طريقة التشغيل (`MANUAL` يدوي / `SCHEDULED` مجدول) |
| `destinations` | JSONB | مصفوفة الوجهات التي تم حفظ الملف فيها بنجاح |
| `checksum` | VARCHAR(64) | كود التوقيع الرقمي (SHA-256) للتأكد من سلامة الملف وخلوه من التلف |
| `status` | VARCHAR(24) | حالة العملية (`SUCCESS`، `FAILED`، `IN_PROGRESS`) |
| `error_message` | TEXT | سبب الفشل بالتفصيل في حال حدوث أي خطأ |
| `created_at` | TIMESTAMPTZ | تاريخ وتوقيت إنشاء النسخة |

## 3. معمارية الواجهة الخلفية (Backend Architecture - NestJS)

جميع الملفات مقسمة طبقاً لمبدأ المسؤولية الواحدة (SRP) بحيث لا يتجاوز أي ملف 200 سطر، وتقع داخل المجلد:
`apps/api/src/modules/backups/`

### المكونات الأساسية:
1. **`backups.controller.ts`**:
   - `POST /api/backups/trigger`: أخذ نسخة احتياطية فورية الآن.
   - `GET /api/backups`: استعراض جدول سجل النسخ (مع ترقيم 25 عنصر/صفحة وفلترة).
   - `GET /api/backups/:id/download`: دفق (Stream) ملف النسخة الاحتياطية للمتصفح للتحميل الفوري على الفلاشة أو الكمبيوتر.
   - `POST /api/backups/:id/restore`: استعادة النظام من نسخة مسجلة سابقة (مع التحقق الأمني).
   - `POST /api/backups/restore-upload`: استعادة النظام عبر رفع ملف خارجي من الفلاشة.
   - `GET /api/backups/settings`: جلب الإعدادات الحالية.
   - `PATCH /api/backups/settings`: تحديث إعدادات المسار المحلي، الجدولة، وسياسة الاحتفاظ.
   - `GET /api/backups/google/auth-url`: بدء عملية ربط Google بنقرة واحدة (OAuth URL).
   - `POST /api/backups/google/callback`: تبادل رمز التحقق وحفظ رموز التحديث.
   - `POST /api/backups/google/disconnect`: إلغاء ربط حساب Google.

2. **`backups.service.ts`**:
   - اكتشاف موقع أداة `pg_dump` و `pg_restore` تلقائياً عبر فحص مسارات Laragon:
     `C:\laragon\bin\postgresql\postgresql\bin\pg_dump.exe` أو متغيرات النظام `PATH`.
   - تنفيذ عملية الاستخراج مع التمرير المباشر عبر `zlib.createGzip()` لضغط الملف فائق السرعة.
   - حساب توقيع SHA-256 أثناء الضغط.
   - استدعاء المشغلات (`Storage Drivers`) لإرسال الملف للوجهات المطلوبة.
   - تطبيق سياسة الاحتفاظ (`Retention Policy`) بحذف النسخ الأقدم من العدد المحدد.

3. **طبقة مشغلات التخزين (`drivers/`):**
   - `local-storage.driver.ts`: الحفظ في المجلد المحدد محلياً أو على الفلاشة.
   - `google-drive.driver.ts`: التعامل مع Google Drive API لإنشاء مجلد السنتر ورفع الملف.
   - `dropbox.driver.ts`: التعامل مع واجهة برمجة تطبيقات Dropbox.

4. **`backups.scheduler.ts`**:
   - تنفيذ الفحص الدوري اليومي عبر مؤقت مجدول (Cron) يعمل في الخلفية لتشغيل النسخ في الوقت المحدد.

## 4. معمارية الواجهة الأمامية (Frontend Architecture - React & Tailwind)

تخصيص شاشة كاملة بمظهر عصري وسلس تقع في:
`apps/web/src/features/backups/` مع إضافة رابطها في القائمة الجانبية للتطبيق (`Sidebar`).

### الشاشات والمكونات:
1. **`backups-page.tsx`**:
   - شريط علوي مع زر **"إنشاء نسخة احتياطية فورية الآن"** (يظهر شريط تحميل تفاعلي لحظي).
   - بطاقات إحصائية: (موعد آخر نسخة، حجمها، حالة النسخ التلقائي، حالة ربط Google Drive).
   - بطاقات ضبط الوجهات:
     - **ربط Google Drive:** يظهر زر "ربط حساب Google" أو بريد الحساب المربوط حالياً مع زر "إلغاء الربط".
     - **مسار الفلاشة أو الديسك توب:** حقل إدخال للمسار المحلي مع زر "فحص المسار وحفظه".
     - **الجدولة الدورية:** خيار تفعيل النسخ اليومي ووقت التنفيذ وعدد النسخ المحتفظ بها.
   - جدول سجل النسخ (باستخدام `ServerDataTable` مع 25 نتيجة في الصفحة، بحث، وفلاتر):
     - اسم الملف، الحجم (MB/KB)، نوع التشغيل، تاريخ الإنشاء، الوجهات المكتملة، الحالة.
     - أزرار الإجراءات: **تحميل مباشر (Download)**، و**استعادة (Restore)**.
2. **`backup-restore-modal.tsx`**:
   - نافذة تأكيد أمنية مشددة عند الرغبة في استعادة قاعدة البيانات (تحذر المشرف من استبدال البيانات الحالية وتطلب إدخال كلمة سر المشرف للتأكيد).
3. **`backup-upload-modal.tsx`**:
   - نافذة لرفع ملف نسخة احتياطية سابقة من الفلاشة أو القرص الصلب واستعادتها.

## 5. الأمان وسلامة البيانات (Enterprise Security Standards)
- **عزل الصلاحيات:** موديول النسخ الاحتياطي محمي بالكامل للمشرف والمالك فقط (`SystemRole.OWNER` أو صلاحية `SYSTEM_MANAGE`).
- **تأكيد الاستعادة:** تتطلب عمليات الاستعادة التحقق من كلمة مرور المشرف الحالية عبر Argon2id لمنع أي استعادة غير مقصودة.
- **سلامة الملفات (Checksum):** فحص كود التجزئة SHA-256 قبل وبعد الاستعادة لضمان عدم تلف الملف أثناء النقل أو التخزين.
- **عدم حجب النظام (Non-Blocking):** جميع عمليات النسخ والاستخراج تتم في عمليات فرعية (Subprocesses) غير حاجزة لمسار الـ Event Loop لضمان استمرار عمل موظفي السنتر وسرعة النظام دون أي بطء.
